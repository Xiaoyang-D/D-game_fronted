# 页面加载与图片展示优化

## 功能

- 首页直接加载，其余页面按路由拆分；切换时保留导航并显示加载提示。
- 帖子卡片和收藏帖子使用服务端摘要、缩略图；详情使用预览图，点击查看原图。旧接口、外链和失效派生图保留原图回退。
- 头像使用服务端提供的两档派生版本，小头像选择 128px，大头像选择 256px，图片加载失败时回退原图及默认头像。
- 游戏目录新鲜期为 5 分钟，相同分页参数共享缓存。首页与导航的不同分页分别缓存，搜索与发帖选择框共享相同目录。后台新增游戏、保存版区后刷新相关缓存。
- 轮播先加载当前图，在当前请求结束后的空闲时间预加载下一张；自动切换等待当前图片请求结束，保留手动切换和错误恢复。
- 关注按钮复用列表携带的关注状态；缺少状态时请求轻量接口，缓存按作者和当前查看者区分。

## 构建和发布

```shell
npm ci
npm test
npm run build
```

将完整 `dist` 发布到静态站点目录，并同步发布匹配的后端版本。保留上一版静态资源一段时间，避免仍打开旧页面的用户遇到资源缺失。

将 [Nginx 性能片段](nginx-performance.example.conf) 合并到当前站点配置，按实际部署调整代理上游，保留现有 WebSocket、TLS 和其他代理配置。检查 `nginx -t` 通过后重载。

带内容哈希的 `/assets/` 使用长期缓存，`index.html` 使用重新验证策略，JSON 和脚本启用 gzip。示例配置沿用站点现有 `root`。

## 历史图片

旧图片需要在新后端运行历史图片补生成任务。即使之前已生成帖子缩略图，新增头像版本也需要从 `afterId: '0'` 重新扫描。任务结束后刷新页面以重新取得派生图地址；未生成的图片继续显示原图。具体接口和进度字段见后端部署说明。

## 验收

1. 首次打开首页不下载编辑器与后台页面代码；切换页面正常显示导航及加载提示。
2. 卡片图片请求缩略图，正文图片请求预览图，查看原图后才下载原图。
3. 头像请求 `.avatar128.*` 或 `.avatar256.*`，收藏列表显示摘要。
4. 反复打开目录菜单不重复请求新鲜缓存；后台修改后目录重新获取。
5. 当前轮播图先请求，下一张在当前请求结束后准备；慢网及图片错误时仍可切换。

回滚时恢复配套的前后端版本及原 Nginx 配置；保留已有上传文件和派生图片。
